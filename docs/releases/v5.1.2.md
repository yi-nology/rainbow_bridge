# Rainbow Bridge v5.1.2

本版在 v5.1.1 的分布式备份恢复基础上，新增同 Pod 管理辅助容器模式。保留现有业务 Deployment、Service 和访问地址，维护任务仍使用临时 Kubernetes Job；备份恢复只暂停业务子进程，不再要求把整个业务 Pod 缩到零或额外部署独立控制台、网关。

## 新增与调整

- 新增 `business-host`：作为业务容器入口监督固定 server 子进程，实际等待业务退出后记录持久证明；新进程启动前核对控制状态、批准的数据代次及实际配置文件 SHA。
- 新增 `maintenance-helper`：同 Pod 的一个辅助容器组合提供静态页面、认证、任务管理和业务反代。业务子进程暂停时，管理员仍能登录、刷新页面、查看任务及继续操作。
- 生命周期显式选择 `pod_sidecar` 或原 `deployment_stop`，默认保留旧部署行为。备份数据流、校验、新数据库/新桶恢复、原数据保留、账号权威及会话失效规则延续 v5.1.1。
- 内部生命周期命令经 Kubernetes 权限与 HMAC 校验，绑定实例、Pod、操作及 token，再通过 Unix socket 转发固定动作；不开放任意命令，对外管理端口拒绝内部控制路径。
- 配置更新等待完整 Secret 目录的实际内容匹配，不通过重启整个 Pod 应用恢复配置。未知退出、丢失证明或控制连接异常保持维护状态。
- 安装包及应用镜像增加两个新入口，并附同 Pod 部署补丁、权限和接入说明。

## 升级与部署

单纯升级镜像不会自动启用网页备份。首次接入仍需专用控制库、最小角色、备份桶和固定 Job 权限，并在受控停服窗口迁移当前管理员认证；不使用默认密码覆盖现有账号。业务配置改用完整 Secret 目录挂载，不用 subPath。

原应用入口 `/app/server` 保留。同 Pod 模式使用 `/app/business-host` 和 `/app/maintenance-helper`，业务子进程监听本地18080，辅助容器承接原8080。原 Service selector、NodePort 和 BasePath 保持。具体配置见[同 Pod 接入说明](https://github.com/yi-nology/rainbow_bridge/blob/v5.1.2/deploy/kubernetes/maintenance-web/pod-sidecar.md)和[补丁模板](https://github.com/yi-nology/rainbow_bridge/blob/v5.1.2/deploy/kubernetes/maintenance-web/pod-sidecar.example.yaml)。模板须按实例核对，不自动执行正式迁移。

恢复保留旧库和旧桶；认证权威迁移后不能直接回退到旧业务账号表，否则可能恢复过时密码。部署前保存一致副本，回退按当前数据及认证状态处理，不覆盖新写入。

## 基础验证

已在独占 PG16、MinIO、Redis 与双 Pod 环境验证基础备份、恢复、数据/资源/发布结果、当前密码保留与旧会话失效；维护期间 Pod UID保持、网页登录/任务可用，真实浏览器备份及中断后的继续/安全回退通过。构建和受影响基础检查通过。

按本轮要求不追加复杂故障矩阵；未将节点分区、磁盘耗尽、长上传等组合故障写为已通过。发布产物与具体运行环境接入分别记录。
