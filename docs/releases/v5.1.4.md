# Rainbow Bridge v5.1.4

本版增加可恢复的临时免鉴权模式，用于测试方直接调用管理接口；默认仍保持原有管理员会话鉴权。

## 新增与调整

- 配置显式设置 `auth.enabled: false` 后，业务管理、配置编辑、资源、环境/渠道、迁移、发布及备份恢复管理 HTTP 接口不要求登录、Token、Cookie、CSRF 或可信来源身份校验。服务器记录临时操作者 `anonymous-admin`，不创建假用户或持久会话。
- 缺省或 `auth.enabled: true` 继续使用原会话机制。保留管理员和密码，可通过配置恢复鉴权；发行默认未关闭鉴权。
- `GET /api/v1/auth/me` 返回明确的 `auth_enabled:false`、临时身份、null 会话、空 CSRF 及实际维护访问范围。网页支持直接进入和刷新工作台，显示“免鉴权模式”，不显示虚构登录/退出或会话过期提示。
- 免鉴权请求层不附带旧 Cookie、Authorization 或 CSRF；维护 HTTP 同步支持无凭据调用，不签发结果只读 Cookie。开启鉴权时保留 Cookie/CSRF/精确来源规则。
- scope、冻结、编辑/生效 revision、request_id、发布步骤、备份恢复确认与维护门控继续有效。内部 IPC、Kubernetes 和数据库权限不变。

## 配置与使用

```yaml
auth:
  enabled: false
```

第三方在此模式下直接请求管理 API，无需先登录或申请 API Token；仍按原接口提供业务参数。API Token 方案未在本版实现。

同 Pod 模式需要同时配置业务 `auth.enabled` 和 console 的 `application.auth.enabled`，并让两个进程加载新配置；旧镜像不认识本版新开关。操作和恢复步骤见 [免鉴权运维说明](https://github.com/yi-nology/rainbow_bridge/blob/v5.1.4/docs/operations/auth-disabled.md)。
