# Rainbow Bridge v5.3.0

本版为破坏性清理版本：对外旧 runtime HTTP 入口退役，兼容别名与死代码清零。

## **BREAKING**：旧 HTTP 入口删除

以下入口在本版起返回 404，不再提供任何兼容层：

- `GET /api/v1/runtime/config`
- `GET /api/v1/runtime/static`

**下游必须迁移**：

| 旧入口 | 迁移目标 |
| --- | --- |
| `GET /api/v1/runtime/config` | `GET /api/v1/runtime/release` |
| `GET /api/v1/runtime/static` | `GET /api/v1/runtime/release/static` |

现行入口用法保持 v5.2.0 契约：读配置带 `x-environment`/`x-pipeline` 头，可选 `version`、`scope_id`、`content_format=json|raw`；静态包同样带头，可选 `version`、`scope_id`、`expected_snapshot_id`。静态包请求从 query 参数（`environment_key`/`pipeline_key`）改为请求头。

差异说明：旧入口对非 UUID 的 `scope_id` 返回 400 `SCOPE_INVALID_REQUEST`；现行入口与 `runtime/release` 口径一致，未知或非法 `scope_id` 统一返回 404 `SCOPE_NOT_FOUND`。

## 同步清理

- service 层删除 `RuntimeReleaseLegacy`、`normalizeLegacyScopeID`、`ExportActiveReleasePackage`（空 pin 兼容转发）与 `GetConfigByKey` 死代码（含 `ConfigDAO.GetByResourceKeyOnly`）；`ExportActiveReleasePackageWithScope` 的 scope pin 校验与现行读入口统一
- 路由注册、`IsPublicRequest` 公开白名单、IDL `RuntimeService` service 项同步删除旧入口
- 管理台前端删除零调用的 `runtimeApi.config`/`runtimeApi.exportStatic` 旧客户端方法与配套类型；`RuntimeRelease`/`RuntimeReleaseWithScope`/`ExportActiveReleasePackageWithScope` 等现行接口不变
- 维护切换验收、e2e/远程探针/性能/Postman 测试资产迁移到现行入口
- `pkg/database/config_alias.go` 配置资源别名约束与 `LegacyLocal`/`LegacyScopeID` 存量数据兼容层为产品特性，本版不动

## 基础验证

`go build ./...`、`go vet ./...`、`go test -race ./...` 全绿；CI 门禁（build/vet/test）通过后合并。tag 推送后按现有 Release 流水线构建安装包和双架构镜像；产物状态以流水线实际结果为准。
